The choice of the code you will harden is yours. 
If you have any application written in C/C++ (ideally also Rust, but we discourage it because ASPIS for Rust is currently under development), you can use that. Otherwise, you can write ad-hoc so-called microbenchmarks to stress specific features of the ASPIS compiler (you can find more information on its functioning in this article: https://dl.acm.org/doi/10.1145/3660524), or use benchmarks that are publicly available (just make sure that licensing allows its use, even better if they allow us to use it into the ASPIS repository). Clearly, the number of benchmarks to harden depends on their complexity. So, once you have identified them, we can discuss whether they are sufficient for the project or not. 
New note on LLM from this year: you can do whatever you want with IA even the whole project. 
Anyhow, you have to declare in the final report whether you have used LLMs and for what purpose.
